3. فضاهای رنگی — Color Spaces (04)

بیشتر درباره‌ی تصاویر RGB (یا در OpenCV در واقع BGR):

جدا کردن کانال‌های تصویر با cv2.split:

img = cv2.imread("./images/color.png") b, g, r = cv2.split(img) # نمایش هر کانال جداگانه به‌صورت gray plt.figure(figsize=[20,5]) plt.subplot(141); plt.imshow(r, cmap='gray'); plt.title("Red Channel") plt.subplot(142); plt.imshow(g, cmap='gray'); plt.title("Green Channel") plt.subplot(143); plt.imshow(b, cmap='gray'); plt.title("Blue Channel") plt.subplot(144); plt.imshow(img[:,:,::-1]); plt.title("all channels")

ترکیب دوباره‌ی کانال‌ها با cv2.merge (خروجی دقیقاً همان تصویر اصلی است):

merged = cv2.merge([b, g, r]) plt.imshow(merged[:,:,::-1])

با صفر کردن دو کانال دیگر، می‌توان هر کانال را به‌تنهایی و با رنگ واقعی‌اش دید (نه فقط خاکستری):

zeros = np.zeros_like(r, 'uint8') red = cv2.merge([zeros, zeros, r]) # فقط کانال قرمز فعال green = cv2.merge([zeros, g, zeros]) # فقط کانال سبز فعال blue = cv2.merge([b, zeros, zeros]) # فقط کانال آبی فعال plt.figure(figsize=[20,5]) plt.subplot(141); plt.imshow(red[...,::-1]); plt.title("Red") plt.subplot(142); plt.imshow(green[...,::-1]); plt.title("Green") plt.subplot(143); plt.imshow(blue[...,::-1]); plt.title("Blue")

تغییر یک کانال به‌تنهایی — و باگ رایج آن

یک اشتباه خیلی رایج، جمع مستقیم روی یک کانال است:

b, g, r = cv2.split(img) modified_b = b + 20 merged = cv2.merge([modified_b, g, r]) plt.imshow(merged[:,:,::-1])
!
می‌تونی حدس بزنی مشکل کجاست؟

چون b از نوع uint8 است (فقط ۰ تا ۲۵۵)، جمع مستقیم b + 20 در مقادیر نزدیک به ۲۵۵ overflow (سرریز) می‌کند — مثلاً ۲۴۵ به‌جای ۲۶۵ می‌شود ۹. نتیجه لکه‌های رنگی عجیب در قسمت‌های روشن تصویر است.

راه‌حل درست: قبل از جمع به int16 تبدیل کن، بعد با clip در بازه‌ی مجاز نگه دار:

modified_b = b.astype('int16') + 20 modified_b = np.minimum(modified_b, 255) modified_b = modified_b.astype('uint8') merged = cv2.merge([modified_b, g, r])

راه بهتر (و کوتاه‌تر) همانی است که در نوت‌بوک عملیات ریاضی می‌بینیم — cv2.add که خودش این saturating را انجام می‌دهد:

assert np.all(modified_b == cv2.add(b, 20)) # هر دو دقیقاً یکسان‌اند

فضای رنگی HSV

در HSV، رنگ (Hue) از روشنایی (Value) جدا شده — همین باعث می‌شود تشخیص رنگ خاص، مستقل از نور محیط، خیلی راحت‌تر باشد. HSV به‌خصوص در فیلترکردن رنگ خیلی مفید است.

فضاهای رنگی بیشتر

OpenCV ده‌ها حالت تبدیل فضای رنگی دیگر هم دارد — اما در عمل خیلی‌هایشان به ندرت لازم می‌شوند؛ BGR، RGB، GRAY و HSV بیشترین کاربرد را دارند. لیست کامل تبدیل‌های رنگ: docs.opencv.org – color conversions

مثال عملی کامل: ردیابی زنده‌ی یک شیء آبی‌رنگ از وب‌کم با ماسک HSV، پیدا کردن بزرگ‌ترین contour، و رسم کادر و مرکز آن روی فریم:

import cv2 import numpy as np cap = cv2.VideoCapture(0) while True: ret, frame = cap.read() hsv = cv2.cvtColor(frame, cv2.COLOR_BGR2HSV) # محدوده رنگ آبی (مثال) lower = np.array([100, 100, 100]) upper = np.array([130, 255, 255]) mask = cv2.inRange(hsv, lower, upper) contours, _ = cv2.findContours(mask, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE) if contours: c = max(contours, key=cv2.contourArea) if cv2.contourArea(c) > 500: x, y, w, h = cv2.boundingRect(c) cx = x + w // 2 cy = y + h // 2 cv2.rectangle(frame, (x, y), (x+w, y+h), (0,255,0), 2) cv2.circle(frame, (cx, cy), 5, (0,0,255), -1) print("Center:", cx, cy) cv2.imshow("Frame", frame) cv2.imshow("Mask", mask) if cv2.waitKey(1) == 27: # کلید ESC break cap.release() cv2.destroyAllWindows()

فرمول ترکیب با آلفا

مقدار α بین ۰ تا ۲۵۵ ذخیره می‌شود که تقسیم بر ۲۵۵ می‌شود (پس ۰ ≤ α ≤ ۱)، و فرمول ترکیب چنین است:

I = α·F + (1-α)·B

  • وقتی α = 0، خروجی همان تصویر پس‌زمینه (B) است.
  • وقتی α = 1، خروجی همان تصویر جلو/شما (F) است.
  • وقتی 0 < α < 1، خروجی ترکیبی از تصویر و پس‌زمینه است.

bitwise_and = cv2.bitwise_and(square, ellipse) # فقط اشتراک دو شکل bitwise_or = cv2.bitwise_or(square, ellipse) # هرجا حداقل یکی از دو شکل باشد bitwise_xor = cv2.bitwise_xor(square, ellipse) # هرجا فقط یکی از دو شکل به‌تنهایی باشد bitwise_not_sq = cv2.bitwise_not(square) # همه‌جا به‌جز مربع plt.figure(figsize=[12,6]) plt.subplot(242); plt.imshow(square,cmap='gray'); plt.title("Square") plt.subplot(243); plt.imshow(ellipse,cmap='gray'); plt.title("Ellipse") plt.subplot(245); plt.imshow(bitwise_and,cmap='gray'); plt.title("And") plt.subplot(246); plt.imshow(bitwise_or,cmap='gray'); plt.title("Or") plt.subplot(247); plt.imshow(bitwise_xor,cmap='gray'); plt.title("Xor") plt.subplot(248); plt.imshow(bitwise_not_sq,cmap='gray'); plt.title("not (square)")

6. عملیات ریاضی — Arithmetic Operations (08)

عملیات ساده‌ای است که به ما این امکان را می‌دهد که به‌طور مستقیم شدت رنگ را اضافه یا کم کنیم. عملیات روی خانه‌های نظیر‌به‌نظیر دو آرایه با ابعاد یکسان انجام می‌شود و نتیجه‌ی نهایی، کاهش یا افزایش روشنایی تصویر خواهد بود.

i
یادآوری: uint8 چیست

تصاویر در OpenCV با نوع داده‌ی uint8 (عدد صحیح بدون‌علامت ۸ بیتی) ذخیره می‌شوند. چون ۸ بیتی است، ۲ به‌توان ۸ یعنی ۲۵۶ عدد مختلف در آن جا می‌گیرد — یعنی فقط بازه‌ی ۰ تا ۲۵۵. مقادیر خارج از این بازه امکان‌پذیر نیست و اگر عددی بزرگ‌تر قرار بدهیم، متغیر سرریز (overflow) می‌شود.

a = np.ones([2], dtype="uint8") b = a * 100 print(b) # [100 100] print(b + 155) # [255 255] -> درست به سقف رسید، هنوز مشکلی نیست print(b + 160) # [4 4] -> سرریز شد! (260 mod 256 = 4)

همین اتفاق وقتی broadcast نشود و دو ماتریس هم‌اندازه را با هم جمع کنیم هم می‌افتد:

m1 = np.array([[150, 155], [156, 157]], dtype="uint8") m2 = np.ones([2,2], dtype="uint8") * 100 print("m1:"); print(m1) print("m2:"); print(m2) print("m1+m2:"); print(m1 + m2) # همه‌جا سرریز شد، چون هر مقدار m1 + 100 از 255 رد می‌شود

راه‌حل ۱: تبدیل موقت به int16، جمع، بعد clip و برگشت به uint8:

modified_m1 = m1.astype('int16') + m2 modified_m1 = np.minimum(modified_m1, 255) modified_m1 = modified_m1.astype('uint8') modified_m1

راه‌حل ۲: با اندیس‌گذاری شرطی (بدون تغییر نوع داده)، مقادیری که از یک آستانه بیشترند مستقیم ۲۵۵ می‌شوند و بقیه به‌سادگی جمع می‌شوند:

m1 = np.array([[150, 155], [156, 157]], dtype="uint8") value_to_add = 100 max_threshold = 255 - value_to_add m1[m1 >= max_threshold] = 255 m1[m1 < max_threshold] += value_to_add print(m1)

راه سوم و ساده‌تر از همه: استفاده از توابع آماده‌ی OpenCV — cv2.add و cv2.subtract این مشکل را اصلاً نشان نمی‌دهند؛ مقادیر کمتر از ۰ همان ۰ باقی می‌مانند و مقادیر بیشتر از ۲۵۵ همان ۲۵۵:

image = cv2.imread('images/input.jpg') # ماتریسی هم‌اندازه‌ی تصویر که همه‌جایش مقدار 100 است M = np.ones(image.shape, dtype="uint8") * 100 added = cv2.add(image, M) # روشن‌تر، بدون سرریز subtracted = cv2.subtract(image, M) # تیره‌تر، بدون منفی شدن plt.figure(figsize=[15,5]) plt.subplot(131); plt.imshow(image[...,::-1]); plt.title("Original") plt.subplot(132); plt.imshow(added[...,::-1]); plt.title("Added") plt.subplot(133); plt.imshow(subtracted[...,::-1]); plt.title("Subtracted")

مثال عملی: ترکیب دو تصویر رنگی

اما اگر دو تصویر هم‌اندازه نباشند چه؟ تکنیک رایج: یک لوگو (تصویر کوچک‌تر) را با np.zeros_like در یک بوم سیاه هم‌اندازه‌ی تصویر اصلی «padding» می‌کنیم و بعد جمع می‌زنیم — چون سیاه (۰) در جمع اثری ندارد:

ترکیب دو تصویر با جمع وزن‌دار (addWeighted)

cv2.addWeighted(src1, alpha, src2, beta, gamma) — فرمول دقیق‌اش:

g(x) = (1−α)·f₀(x) + α·f₁(x)   یا معادل آن: dst = α·img1 + β·img2 + γ

7. روشنایی و کنتراست — خطی و گاما (09, 10)

در نوت‌بوک قبلی، تاثیر جمع/تفریق یک مقدار ثابت روی روشنایی (brightness) تصویر را دیدیم. حالا علاوه بر روشنایی، کنتراست (contrast) تصویر را هم بررسی می‌کنیم — و مشکلات این روش خطی را هم می‌بینیم.

g(x) = α·f(x) + β   (α > 0)

پارامترهای α و β معمولاً gain و bias نامیده می‌شوند؛ گاهی هم می‌گویند این دو به‌ترتیب کنتراست و روشنایی را کنترل می‌کنند.

با تابع convertScaleAbs

image = cv2.imread("images/input.jpg") alpha = float(input('* Enter the alpha value [0.1-3.0]: ')) beta = int(input('* Enter the beta value [0-100]: ')) new_image = cv2.convertScaleAbs(image, alpha=alpha, beta=beta) plt.figure(figsize=[15,5]) plt.subplot(121); plt.imshow(image[...,::-1]); plt.title("Original") plt.subplot(122); plt.imshow(new_image[...,::-1]); plt.title("Output")

همین فرمول را می‌شود پیکسل‌به‌پیکسل هم پیاده‌سازی کرد — با فرض i شماره سطر و j شماره ستون: g(i,j) = α·f(i,j) + β

new_image2 = np.zeros(image.shape, image.dtype) # به‌جای این حلقه‌های تودرتو می‌شد فقط از convertScaleAbs استفاده کرد # اما هدف اینجا نشون‌دادن نحوه‌ی دسترسی مستقیم به پیکسل‌هاست :) for y in range(image.shape[0]): for x in range(image.shape[1]): for c in range(image.shape[2]): new_image2[y,x,c] = np.clip(alpha*image[y,x,c] + beta, 0, 255) plt.figure(figsize=[15,5]) plt.subplot(121); plt.imshow(image[...,::-1]); plt.title("Original") plt.subplot(122); plt.imshow(new_image2[...,::-1]); plt.title("Output")
!
آیا دو روش بالا دقیقاً یکی هستند؟

در تئوری هر دو یک فرمول را پیاده می‌کنند، اما حلقه‌ی پیکسل‌به‌پیکسل به‌شدت کند است (روی تصاویر بزرگ ممکن است چند ثانیه طول بکشد)، در حالی که convertScaleAbs یک عملیات برداری بهینه‌شده در سطح C++ است. همیشه در عمل از convertScaleAbs استفاده کنید.

مشکل این روش چیست؟

تنظیم خطی روی همه‌ی پیکسل‌ها یکنواخت اثر می‌گذارد، اما چشم انسان به روشنایی به‌صورت غیرخطی (لگاریتمی) حساس است. این مشکل در نوت‌بوک بعدی (تصحیح گاما) حل می‌شود.

تنظیم روشنایی و کنتراست با تصحیح گاما (10)

تصحیح گاما را می‌توان برای اصلاح روشنایی یک تصویر با استفاده از یک تبدیل غیرخطی بین مقادیر ورودی و خروجی استفاده کرد:

O = (I / 255)^γ × 255

از آنجا که این رابطه غیرخطی است، اثر آن برای همه‌ی پیکسل‌ها یکسان نیست و به مقدار اصلی خودشان بستگی دارد — برخلاف تنظیم خطی که همه را به یک اندازه جابه‌جا می‌کند.

مقدار گامااثر
γ < 1مناطق تاریک تصویر روشن‌تر می‌شوند و هیستوگرام به سمت راست منتقل می‌شود
γ > 1برعکس حالت بالا: مناطق روشن تیره‌تر می‌شوند و هیستوگرام به چپ منتقل می‌شود

مثال: تصحیح یک تصویر کم‌نور (underexposed) با استفاده از یک Look-Up Table — چون گاما برای هر مقدار پیکسل ورودی (۰ تا ۲۵۵) از قبل محاسبه‌شدنی است، به‌جای محاسبه برای هر پیکسل، یک جدول ۲۵۶‌تایی می‌سازیم و با cv2.LUT یک‌جا اعمالش می‌کنیم — این کار خیلی سریع‌تر از حلقه زدن است:

gamma = 0.4 img_original = cv2.imread("images/room-light.jpg") lookUpTable = np.empty((1,256), np.uint8) for i in range(256): lookUpTable[0,i] = np.clip(pow(i / 255.0, gamma) * 255.0, 0, 255) out = cv2.LUT(img_original, lookUpTable) plt.figure(figsize=[15,5]) plt.subplot(121); plt.imshow(img_original[...,::-1]); plt.title("Original") plt.subplot(122); plt.imshow(out[...,::-1]); plt.title("Output")

مقایسه‌ی مستقیم: روش خطی در برابر گاما

gamma = 0.4 img_original1 = cv2.imread("images/aa.jpg") img_original2 = cv2.imread("images/asalooye.jpg") output_linear1 = cv2.convertScaleAbs(img_original1, alpha=1.3, beta=40) output_linear2 = cv2.convertScaleAbs(img_original2, alpha=1.3, beta=40) lookUpTable = np.empty((1,256), np.uint8) for i in range(256): lookUpTable[0,i] = np.clip(pow(i / 255.0, gamma) * 255.0, 0, 255) output_gammacorrected1 = cv2.LUT(img_original1, lookUpTable) output_gammacorrected2 = cv2.LUT(img_original2, lookUpTable) plt.figure(figsize=[17,6]) plt.subplot(231); plt.imshow(img_original1[...,::-1]); plt.title("Original") plt.subplot(232); plt.imshow(output_linear1[...,::-1]); plt.title("Linear") plt.subplot(233); plt.imshow(output_gammacorrected1[...,::-1]); plt.title("Gamma") plt.subplot(234); plt.imshow(img_original2[...,::-1]); plt.title("Original") plt.subplot(235); plt.imshow(output_linear2[...,::-1]); plt.title("Linear") plt.subplot(236); plt.imshow(output_gammacorrected2[...,::-1]); plt.title("Gamma")

نکته‌ی کلیدی مقایسه

با اینکه هر دو روش (خطی و گاما) هدفشان روشن‌تر کردن تصویر است، خروجی گاما معمولاً طبیعی‌تر به نظر می‌رسد چون نواحی که از قبل روشن بودند بیش‌ازحد نمی‌سوزند (over-expose نمی‌شوند)، در حالی که روش خطی چون به همه‌ی پیکسل‌ها یک مقدار ثابت اضافه می‌کند، ممکن است نواحی روشن را کاملاً سفید کند.

جمع‌بندی ماژول 1

  • تصویر = آرایه‌ی NumPy؛ هر چیزی که در NumPy بلدید (slicing, broadcasting, dtype) اینجا هم کاربرد دارد.
  • OpenCV پیش‌فرض روی BGR کار می‌کند، نه RGB.
  • مختصات رسم (x, y) هستند؛ اندیس‌گذاری آرایه [y, x] است.
  • توابع OpenCV مثل cv2.add معمولاً saturating هستند؛ عملیات خام NumPy روی uint8 overflow می‌کند — راه‌حل‌های دستی هم شامل تبدیل به int16+clip و هم اندیس‌گذاری شرطی می‌شود.
  • HSV برای تشخیص رنگ، و ماسک‌های باینری (که در سطح بیت عمل می‌کنند) برای ترکیب/جداسازی نواحی، ابزارهای پایه‌ای پرکاربردند.
  • نوشتن متن فارسی روی تصویر نیاز به مسیر جداگانه (arabic_reshaper + bidi + Pillow) دارد؛ cv2.putText معمولی از پس آن برنمی‌آید.
  • برای روشن/تیره‌کردن تصویر، تصحیح گاما (غیرخطی) معمولاً نتیجه‌ی طبیعی‌تری از تنظیم خطی (alpha/beta) می‌دهد.
